# Failure analysis: math100-v1, Model A

Generated by `python -m evaluation.failure_analysis` from per-image results;
the machine-readable versions are `evaluation/reports/failure_analysis.json`
(all 100 images, run `model_a_v2-all`) and
`evaluation/reports/failure_analysis_test.json` (held-out test split, run
`model_a_v2-test-t600`). Side-by-side pictures (source | tactile SVG) for the
test split are in `evaluation/reports/examples/model_a_v2-all/`.

Root causes are assigned by deterministic rules in `failure_analysis.causes()`
from the scored output (e.g. "a ground-truth label was missed or misread",
"more than half the false positives lie on text"), not by hand. One image can
have several causes. They are diagnoses of where the error shows up, which
is good for prioritising, but they are not proof of the mechanism.

## Ranking

```
badness = 3 * (1 - essential recall) + (1 - label recall) + false-positive share + (1 if QA blocks)
failed image (error/timeout) = 10
```

Severity: `critical` = failed or QA-blocked; `high` = essential recall below
0.5; `medium` otherwise.

## Root causes across all 100 images

| Root cause | Images | Proposed fix |
|---|---:|---|
| `ocr_misread_or_missed` | 74 | upscale label crops before OCR; restrict charset for single-letter labels |
| `type_vocabulary` | 52 | add ray/arrow/tick/axis types to Model A's vocabulary |
| `label_association` | 45 | associate labels to nearest vertex/segment with a distance budget |
| `closed_shape_split` | 32 | join sides into triangles/polygons when endpoints coincide |
| `binarisation_noise` | 24 | grain-aware enhancement; adaptive threshold tuned for photos; learned foreground mask |
| `right_angle_marker_missed` | 21 | detect markers at T-junctions (foot of an altitude), not only where two edges end |
| `text_vectorised_as_geometry` | 17 | mask OCR text boxes before vectorisation |
| `small_features_dropped` | 6 | keep short strokes that touch a number line or axis; tick detector |
| `timeout_noise_explosion` | 1 | denoise before binarising; cap contour count per region; process large photos at reduced scale |
| `other` | 5 | investigate |

OCR is the largest single problem: label detection recall is 0.33 across the
benchmark, and 0.08 on `very_hard`. When a label is found, its character error
rate is 0.24, so most of the label error is labels never found, not misreads.

Right-angle markers are never found (recall 0.000, 21 images affected).
Inspection of `math_021` shows why: the detector in
`backend/app/services/right_angles.py` only looks for a marker at a corner
where two extracted edges *end*. Generated markers sit at the foot of an
altitude, which is a T-junction, so no candidate corner exists. This is a
detector limitation, recorded here and not fixed in this PR.

Model B never lowered badness on the test split. That is expected from the
design: an accepted finding can retype or confirm a Model A element, but it
cannot add geometry, find a missed label, or change a coordinate, and the
badness score is driven by missed geometry and missed labels. Its measured
effect is on object type accuracy (see `ACCURACY_REPORT.md`). In 10 of 15
images the free provider returned no usable answer at all.

U-Net helped on 5 of 15 images, made one worse, and left 9 unchanged; none of
the OCR-driven failures change, because the mask only affects vectorisation.

## What to fix first (by images affected and by what the design allows)

1. **OCR label recall** (74 images): crop and upscale around candidate label
   blobs instead of full-page OCR; restrict the charset for single letters.
   This also addresses NCERT latency, where full-page EasyOCR dominates.
2. **Type vocabulary** (52): let Model A emit `axes`/`arrow`/`ray` from
   arrowhead and tick detection. Teacher-accepted Model B findings can already
   retype these, and do so correctly in 6 of 7 paired cases, but only when the
   free provider answers.
3. **Closed shapes split into sides** (32): join segments into
   triangles/polygons when endpoints coincide within tolerance.
4. **Right-angle markers at T-junctions** (21): extend
   `detect_right_angle_markers` to look for a small square against a
   continuing line.
5. **Noise and text strokes** (24 + 17): mask OCR boxes before vectorising;
   the U-Net pilot shows a learned foreground mask removes much of this on
   synthetic data.
